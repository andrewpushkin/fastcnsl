02 Speed tests

Measured against the terminals you already have

Each test prints a 32 MiB file with cat and times it. A terminal that is slow at this makes long builds and logs wait for it. Shorter bars are better.

3.3×

faster than Windows Terminal at coloured output in a WSL tab

2.4×

faster than Windows Terminal when 16 tabs print at the same time

4.4×

faster than GNOME Terminal, the next best on Linux, with 16 tabs

On Windows

Windows 11, Ryzen 9 7940HX. fastcnsl 0.1.124 on DirectX 12 against Windows Terminal 1.24 and the classic console (conhost), all with default settings.

What the speed costs

fastcnsl takes 454 ms to open a window, most of it setting up DirectX 12. A Windows Terminal that is already running opens one in 167 ms, the classic console in 79 ms. An idle fastcnsl window uses 107 MB of memory.

On output made of many short lines, fastcnsl and Windows Terminal tie. Output from cmd and PowerShell takes the same time in all three terminals, because there the Windows console itself is the limit.

On Linux

Ubuntu 26.04 on the same machine, GPU rendering. fastcnsl 0.1.122 against GNOME Terminal 3.58, Ptyxis 50.1 (Ubuntu's default terminal), Konsole 25.12 and xterm 407.

What the speed costs

Memory. An idle fastcnsl window uses 180 MB, against 40 MB for GNOME Terminal and 13 MB for xterm, and it keeps everything a tab printed, so 16 tabs with 512 MiB of output grow to about 1 GB. xterm and GNOME Terminal also open a window faster.

Measured on 11 November 2026. The time is the wall time of cat FILE inside the terminal. The full results have every table, including startup, CPU, memory and opening 100 windows, where fastcnsl is not always first, and the commands to run the benchmark on your own machine.

03 Why fastcnsl

Why fastcnsl is the best

It prints faster than the other terminals in the tests above, and it does things with your output that they don't.

01

Search marks every match, in up to eight colours

Press Ctrl+Shift+F and type. Every match on screen is marked the way Notepad++ does it, and 3/17 tells you where you are in the whole scrollback. Add a second search and it gets its own colour, so you can follow several words through a log at once. Regular expressions work too.

02

You can come back to any line

Scrollback has no limit: a tab keeps everything it printed, in memory up to 500 MB and in a temporary file after that. Bookmark a line with Ctrl+Shift+B and jump between bookmarks. Save a tab's text, or log it to a file as it arrives.

03

It is the fastest at large output

It finishes first in every cat test on Linux and in the plain text, colour and Unicode tests on Windows. Windows Terminal takes 2.5 times longer for coloured text than for plain text. fastcnsl is just as fast with both.

04

Tabs don't wait for each other

Each tab reads and parses its output on its own thread. A long build in one tab doesn't slow the others, and a bell on the tab tells you when it printed something.

05

It shows when each line appeared

The left margin has the time you ran each command and, for every line of output, how many seconds later it arrived. You can see at a glance which step of a build was slow.

06

Code is coloured when you print it

cat, type, Get-Content or git diff a source file and fastcnsl colours it. It works out the language from the file name or the content.

07

AI fixes the command, and you run it

Ctrl+Shift+X sends the failed command and its output to ChatGPT, Grok or Claude, which types the corrected command at your prompt without running it. It can use the plan you already pay for, or free models through OpenRouter.

08

One terminal for cmd, PowerShell and WSL

WSL tabs skip the Windows console host, which is why they are fast. It follows your light or dark theme, and fastcnsl new-tab opens tabs from scripts.
